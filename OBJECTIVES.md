# Objectives

The destination for every skill in this assistant.

The current rubric is lifted from *The Missing Readme* by Chris Riccomini and Dmitriy Ryaboy (Chapter 1, "The Journey Ahead"). It captures four dimensions of becoming a strong software engineer. Every skill in this assistant should make the needle move on at least one of them — if a skill doesn't, it doesn't belong here.

As more sources arrive, the rubric may be enriched. The four pillars below are the foundation, not the ceiling.

## The Four Pillars

**1. Technical Knowledge**
We know our computer science fundamentals. We know how to use IDEs, build systems, debuggers, and test frameworks. We are familiar with continuous integration, metrics and monitoring, configuration, and packaging systems. We proactively create and improve test code. We consider operations when making architectural decisions.

**2. Execution**
We create value by solving problems with code and understand the connection between our work and the business. We have built and deployed small and medium-sized features. We write, test, and review code. We share on-call duties and debug operational issues. We are proactive and dependable. We participate in technical talks, reading groups, interviews, and presentations.

**3. Communication**
We communicate clearly in both written and verbal form. We are able to give and receive feedback effectively. We proactively ask for help and get clarification in ambiguous situations. We raise issues and identify problems in a constructive manner. We provide help when possible and are starting to influence peers. We document our work. We write clear design documents and invite feedback. We are patient and empathetic when dealing with others.

**4. Leadership**
We work independently on well-scoped work. We learn from mistakes quickly. We handle change and ambiguity well. We actively participate in project and quarterly planning. We help new team members onboard. We give meaningful feedback to our manager.

## How we use these

Every skill in this assistant declares the pillar(s) it strengthens. When designing a new skill, the first question is: *which pillar does this make better, and how?* If the answer isn't clear, the skill probably isn't focused enough yet.

The four pillars also keep the assistant honest. It would be easy to accumulate a pile of skills that all reinforce Execution (because tactical advice is the easiest to package) while leaving Communication and Leadership thin. The rubric is here so we notice that imbalance and correct it.
